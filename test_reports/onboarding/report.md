## Bugs

1. **Saved model load failure stays on Home (high).** Reproduce: after one successful setup, force-stop; replace the file at the saved `model_file_path` with an empty `.gguf` while keeping its path; relaunch. Expected: onboarding error with Try again and file-picker recovery, because no model is ready. Actual: Home remains visible; Text shows a stale “Loading model into memory…” banner, while Settings reports `LlamaException: Model file is empty` and offers download. Gate condition `isReady || hasModel` in `lib/ui/screens/app_gate.dart:37` treats file existence as readiness even after `ModelStatus.error`. [Home](bad_saved_model_home.png), [Settings error](bad_saved_model_settings.png). The valid model was restored and [verified ready](restored_ready.png).

2. **Text status does not refresh when an existing model becomes ready (medium).** Reproduce: force-stop and relaunch with a valid saved model. Wait until Settings reports “Model ready”, then return to Text. Expected: loading banner disappears as soon as the manager becomes ready. Actual: the banner persists, including after switching tabs, until text input forces a rebuild. `HomeScreen` caches tab widgets in `_screens` (`lib/ui/screens/home_screen.dart:39`), and Text reads `isReady` only during its own build (`lib/ui/screens/text_translation_screen.dart:178-200`). `AppGate` starts Home while the model loads (`lib/ui/screens/app_gate.dart:37`), exposing this stale state. [Stale Text](relaunch_after30.png), [ready Settings](relaunch_settings.png), [cleared after input](relaunch_after_input.png).

3. **Network errors expose a long raw storage URL (low).** Reproduce: interrupt connectivity during download and wait for the connection to close. Expected: a concise localized error with the retry action. Actual: the error card contains `ClientException` plus a multi-line signed Cloudflare URL and SHA path; it fills much of the screen. `ModelManager` stores the raw exception at `lib/core/model/model_manager.dart:341`; onboarding displays it unbounded at `lib/ui/screens/onboarding_screen.dart:236`. [Interrupted connection](download_mid.png). Try again remains reachable.

## Notes and limits

- The file-picker route was not exercised with a valid external GGUF. `/sdcard/Download/hy-mt2.gguf` was absent, and the full in-app download completed, so the fallback was unnecessary. The button and `pickModelFile()` call were verified by UI and source review.
- Onboarding offers no in-app language switch. Turkish can still be selected through Android per-app language settings, as used for the screenshot.
- The app's Flutter log lines showed normal engine startup, including `10-20 10:14:20.762 ... I flutter : ... Using the Impeller rendering backend (OpenGLES)` and `10-20 10:14:20.853 ... I flutter : The Dart VM service is listening ...`.
